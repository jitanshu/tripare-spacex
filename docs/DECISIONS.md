# Decisions

## Expo Prebuild Instead Of Plain RN CLI

The original brief asked for bare React Native. The follow-up instruction changed that to an Expo ejected version, so the project uses Expo with committed `ios/` and `android/` folders generated by `expo prebuild`. This preserves native project control while making the scaffold reproducible.

## Expo SQLite

SQLite is the primary structured store because the dataset is relational, queryable, and must survive offline use. WatermelonDB would be reasonable for very large collaborative datasets, but SQLite is simpler, smaller, and sufficient for SpaceX launch and launchpad records.

## React Query

React Query handles sync deduplication, stale data, retry, and exponential backoff. SQLite remains the source of durable truth; React Query is the orchestration/read-through layer for screens.

## SpaceX API 525 Fallback

On September 4, 2026, the original `https://api.spacexdata.com` host returns Cloudflare/TLS 525 failures because the community API was archived in June 2026. The client still tries the assignment URL first, then falls back to the Pipeworx SpaceX mirror at `https://gateway.pipeworx.io/spacex/v4/launches`. The mirror schema is simplified, so the app synthesizes stable launch IDs and uses a small canonical launchpad catalog when the mirror omits pad data.

## Zustand

Zustand stores UI state such as filters and the sync banner. It avoids Redux boilerplate while still keeping state transitions explicit and testable enough for a take-home app.

## Encryption

Bookmark notes are encrypted before writing to SQLite using AES from `crypto-js`. The encryption key is generated on-device and stored in Expo SecureStore. This is not plaintext masking; database contents contain ciphertext. A production hardening pass would replace `crypto-js` with a native maintained AES/GCM module after confirming Expo SDK compatibility.

## Maps And Clustering

`react-native-maps` renders both single-pad and multi-pad views. The clustering function buckets nearby pads based on zoom-derived coordinate precision, sums launch density, and colors pins by attempts. This keeps marker count small for the assignment dataset while avoiding a heavyweight clustering dependency.

## Image Caching

Mission patches use `expo-image` with disk cache. `.env.example` documents a 64 MB target cap; enforcing eviction telemetry at runtime is left as future hardening because Expo Image owns the platform cache.

## Bonus Items

The user selected `none`, so E2E tests, full screen-reader support, CI/CD, advanced AND/OR filters, JSON export, and shared-element animations were deliberately excluded to keep the build focused on the core spec.
